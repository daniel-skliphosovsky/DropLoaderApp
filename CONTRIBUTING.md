# Contributing

Thank you for your interest in contributing to MediaHub! This document outlines the contribution process and guidelines.

## How to Start

1. **Fork the repository** on GitHub
2. **Create a new branch** for your changes:
   ```bash
   git checkout -b feature/your-feature-name
   ```
3. **Make your changes** following the project's coding standards
4. **Test your changes** thoroughly
5. **Commit your changes** with a descriptive message
6. **Push to your fork**
7. **Open a pull request** against the main branch

## Reporting Bugs

When reporting a bug, please include:

- **Version**: The version of MediaHub you are using (e.g., v4.1.0)
- **Platform**: Windows or macOS
- **Environment**: Any relevant system information
- **Steps to reproduce**: Clear, numbered steps that lead to the bug
- **Expected behavior**: What should happen
- **Actual behavior**: What actually happens
- **Additional details**: Screenshots, error messages, or any other helpful information

## Feature Requests

To request a new feature:

1. **Check existing issues** to see if the feature has already been requested
2. **Open a new issue** with:
   - **Problem/Goal**: Clear description of what you want to achieve
   - **Proposed solution**: How you think it could be implemented (optional)
   - **Alternatives**: Other approaches you've considered (optional)
   - **Additional context**: Any relevant information

## Pull Request Process

1. **Ensure your changes pass all tests** (if any)
2. **Run the build** to verify everything compiles correctly
3. **Update the changelog** if your changes are significant
4. **Create a pull request** with:
   - **Clear title**: Describing the changes
   - **Detailed description**: Explaining what was changed and why
   - **Checklist**: Verify all requirements are met

## Code of Conduct

Please refer to the [Code of Conduct](CODE_OF_CONDUCT.md) for guidelines on maintaining a respectful and professional community.

## Style Guidelines

- Follow the existing code style and conventions
- Write clear, concise commit messages
- Add comments for complex logic
- Ensure code is properly formatted
- Test thoroughly before submitting changes

## Getting Help

If you have questions about contributing:

1. **Check the documentation** in the repository
2. **Ask in a GitHub issue** with the `question` label
3. **Join the discussion** on relevant issues

## Thank You!

Your contributions help make MediaHub better for everyone. We appreciate your time and effort!
